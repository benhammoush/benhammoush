# Profile maintenance

Source for the public profile README at `benhammoush/benhammoush`. Edit `profile.json` for personal details. The original Matrix animation combines green character rain and the information panel into a GIF; a static PNG is saved in `assets/profile.png`.

## Counting rules

- **Repos:** token-visible public and private repositories owned by `benhammoush`, excluding forks. Includes empty, archived, and profile repositories.
- **Commits:** distinct commit SHAs authored by the GitHub account in eligible repositories' default-branch histories. The profile repository is excluded from commit and activity statistics to prevent generated assets from inflating them.
- **PRs:** authored public and private pull requests visible to the token, across all owners and all states, from GitHub issue search. Search indexing can lag.
- **Green (+N):** activity in the rolling 24 hours ending at the start of the last successful refresh, hidden when zero. PRs use creation time; commits use their Git committed timestamp, not push/merge time.
- **Lines:** current source-code lines on each eligible repository's pinned default-branch tip, excluding the profile repository. Includes code by any author, not just the account owner. `cloc` 2.08 supplies physical code-line counts, excluding comments and blank lines. Identical files at different tracked paths or in different repositories count separately. Only regular tracked files count; symlinks, submodules, binary files containing NUL bytes, and LFS pointers are excluded.
- **Line activity (+/-):** authored additions and deletions in the **last 24 hours only**, using the same committed-time window as the recent commit counter. Both remain visible when zero. These are activity figures, not the change in the current line total. Lifetime `additions` and `deletions` remain in the stats JSON for compatibility but no longer determine `lines`.

Future-dated commits are excluded from recent activity. Commits only on unmerged branches, commits in other owners' repositories, repositories the token cannot access, and author emails GitHub cannot associate with the account are excluded from authored statistics. Squash merges count as their resulting commit. Identical SHAs are counted once across repositories for commit and activity statistics, not current line totals. Each repository's branch tip is pinned during pagination and that same revision is fetched for its line count; the overall refresh is not a cross-repository atomic snapshot. Empty repositories contribute zero lines. The inclusive UTC window is computed once per refresh. Daily snapshot counts are not live and can be almost a day old.

### Source exclusions

The counter excludes these directory names at any depth: `node_modules`, `vendor`, `.venv`, `venv`, `__pycache__`, `.next`, `.nuxt`, `.output`, `dist`, `build`, `out`, `coverage`, `htmlcov`, `target`, `generated`, `__generated__`, `.git`, `.cache`, and `.turbo`.

Generated filenames containing a delimited `generated`, `gen`, or `min`, along with `.g.*`, `.designer.*`, `.d.ts`, and common package lockfiles, are excluded. `cloc` also applies its built-in `--no-autogen` rules and excludes files containing `auto-generated`, `auto generated`, `automatically generated`, `@generated`, or `<auto-generated` markers. These are heuristic filters: an unmarked generated file or vendored library outside the excluded directories may still count, while a handwritten file matching a rule will not.

Documentation/configuration languages `Text`, `Markdown`, `reStructuredText`, `JSON`, `YAML`, `TOML`, `INI`, `XML`, `CSV`, and `SVG` do not count. Other languages use cloc's built-in recognition; unsupported languages do not count. `.mq5` and `.mqh` use the C++ counter for MQL5's C-style comments. This measures physical code lines, not statements or individual authorship.

## Local refresh

Python 3.13, Pillow 13.0.0, Git, and [cloc 2.08](https://github.com/AlDanial/cloc/releases/tag/v2.08) on PATH. The cloc source script requires Perl; the Windows executable does not. The generator uses Consolas on Windows or DejaVu Sans Mono on Linux. Ubuntu GitHub-hosted runners include Git, Perl, and DejaVu fonts; different system fonts can produce small typography differences.

```powershell
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
$env:GITHUB_TOKEN = gh auth token
try { .venv/Scripts/python update_profile.py } finally { Remove-Item Env:GITHUB_TOKEN }
.venv/Scripts/python -m unittest discover -s tests -v
```

The token must belong to the account in `profile.json` and have access to the private repositories to include. Only aggregate numbers are saved and logged, never repository names, commit IDs, or source code. These public totals and their history reveal private activity, including recent activity. No token is stored in output. To regenerate artwork with existing saved stats without fetching GitHub data, run `.venv/Scripts/python generate_matrix.py`. Existing saved totals retain their old meaning until a successful collection refresh replaces them; rendering alone does not recount lines.

For current lines, each nonempty eligible repository is fetched shallowly at its pinned commit into a temporary bare Git repository. Regular blobs passing the path filters are read with `git cat-file --batch` and exported to isolated numbered directories for cloc; original directory paths are never used for export. Temporary repositories and exported files are removed afterward. Repository content is not executed, checkout filters are not applied, and LFS objects/submodules are not fetched. Files above 1 GB and filenames that cannot be safely materialized across platforms abort the refresh rather than silently publishing partial counts.

Git authentication uses a GitHub-scoped authorization header in the subprocess environment, not a credential-bearing URL or saved configuration. The cloc subprocess does not receive that token or Git-specific environment variables. Git/cloc command failures, invalid reports and timeouts abort the refresh without replacing published assets or logging raw subprocess errors. Each command has a 15-minute timeout; the workflow's overall 30-minute limit still applies. Fetching downloads current tracked blobs, including excluded binaries/dependencies, and batch reads hold selected blobs in memory. Bandwidth, memory, disk and runtime therefore grow with repository size.

## Automated refresh

GitHub HTTP 500, 502, 503, and 504 responses are retried up to three times per request, waiting 2, 4, then 8 seconds. If a commit-history page still fails with one of these responses, or its GraphQL errors are all `SERVICE_UNAVAILABLE`, the collector repeats that page without line counts and obtains each previously unseen commit's additions and deletions from the REST commit endpoint. The author filter, cursor, pinned tip, commit dates and SHA deduplication remain unchanged. REST uses commit-level `stats`, not the paginated file list; missing, invalid or mismatched commit statistics abort the refresh. This backup adds up to one REST request per unseen commit on the affected page. Authentication, rate-limit and other GraphQL errors do not trigger the backup; failures in the backup still abort without replacing existing assets.

Commit history is fetched in pages of 10 to reduce per-request work for line statistics and the risk of GitHub's server-side query timeout. All pages are still collected from each pinned branch tip; smaller pages do not truncate totals, but increase API requests and can increase total refresh time.

The workflow runs at approximately **05:23 UTC daily** or via **Run workflow**. It installs the pinned Pillow dependency and the official cloc 2.08 script, runs offline tests (including a real Git/cloc fixture), fetches stats, and generates the 80-frame, 12-second GIF and static PNG. Configure the repository Actions secret `PROFILE_STATS_TOKEN` with a personal access token belonging to `benhammoush`. The collector uses it only for reading statistics; checkout and pushing generated assets still use the built-in `GITHUB_TOKEN`. A missing secret fails the refresh without falling back to public-only totals. Unrecovered API failures, rate limits, incomplete searches, or render/validation errors fail before replacing existing output. Only changed `assets/profile.gif`, `assets/profile.png`, and `assets/stats.json` are committed.

Prefer an expiring fine-grained token with resource owner `benhammoush`, all repositories for full owned-repository coverage, and read-only **Contents** permission (Metadata read is included; issue/PR search requires no additional permission). Selected repositories produce selected-repository totals, not account-wide totals. Fine-grained tokens are limited to one resource owner; private PRs elsewhere are included only when the token can access them. A classic token with `repo` scope can cover more owners subject to organization/SSO policies, but also grants write access and is not read-only. Never grant broader access merely to inflate statistics. Token access restrictions can silently omit repositories; the script cannot prove complete account-wide coverage. Renew the secret before its token expires.

GitHub may delay schedules, cache images, or disable scheduled workflows in inactive public repositories after 60 days. Branch protection may prevent the workflow from pushing; inspect Actions failures rather than weakening protections automatically. GIF animation cannot reliably respect reduced-motion settings in GitHub READMEs. The README intentionally shows only the animation, with empty alt text at the owner's request; profile information is not exposed to screen readers through that image. The static PNG and stats JSON are available directly in `assets`. Image text is rasterized and email inside the image is not clickable.
